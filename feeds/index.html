Set it up

iptables with ipset

Loads the list into an ipset and drops matching traffic. Re-run the first command from cron every 6 hours to stay current.

curl -sS https://neilweitzel.github.io/xfeeds/iptables.ipset | sudo ipset restore -!
sudo iptables -I INPUT -m set --match-set xfeeds src -j DROP

IPv6

An ipset holds one address family, so IPv6 needs its own set and its own rule. Skip this if you are single-stack IPv4.

curl -sS https://neilweitzel.github.io/xfeeds/iptables6.ipset | sudo ipset restore -!
sudo ip6tables -I INPUT -m set --match-set xfeeds6 src -j DROP

Keep it updated

# /etc/cron.d/xfeeds
17 */6 * * * root curl -sS https://neilweitzel.github.io/xfeeds/iptables.ipset | ipset restore -!
17 */6 * * * root curl -sS https://neilweitzel.github.io/xfeeds/iptables6.ipset | ipset restore -!

nftables

curl -sSO https://neilweitzel.github.io/xfeeds/nftables.conf
sudo nft -f nftables.conf

Then reference the set in your ruleset:

nft add rule inet filter input ip saddr @blocklist4 drop

pfSense or OPNsense

Both can fetch a URL table on a schedule — no scripting needed.

Firewall → Aliases → Add
  Type: URL Table (IPs)
  URL:  https://neilweitzel.github.io/xfeeds/high-confidence.txt
  Update frequency: 1 day

Then Firewall → Rules → WAN → Add
  Action: Block
  Source: the alias you just created

MikroTik RouterOS

/tool fetch url="https://neilweitzel.github.io/xfeeds/high-confidence.txt" dst-path=xfeeds.txt
/import file-name=xfeeds.txt

Or use an address list with a scheduled script. Note that RouterOS does not skip # comment lines automatically — strip them first.

Cloudflare

Create an IP Access Rule list from the feed. The free plan caps custom lists, so the high-confidence tier is the right one to use.

curl -sS https://neilweitzel.github.io/xfeeds/high-confidence.txt | grep -v '^#' > xfeeds.txt
# Then: Cloudflare dashboard → Manage Account → Configurations
#       → Lists → Create new list → upload xfeeds.txt

MISP

Sync Actions → Feeds → Add Feed
  Input Source: Network
  Format: MISP
  URL: https://neilweitzel.github.io/xfeeds/misp-manifest.json

512 equal slices of 8,388,608 addresses, so no bar points at an individual addressThe slicing is deliberate. A per-address chart would be the restricted data itself in a thin disguise, so occupancy is only ever shown at slice resolution.. Gaps are as informative as spikesA gap is either a reserved range or a large allocation nobody has reported to us. Height is log-scaled, because linear scaling flattens everything except the two or three busiest slices..

Nothing corroborates them, and nothing covers for them if that source degrades..

Widest entry is a /29. Wide on purpose, not recklessly aggregatedGeneral IPv6 practice treats a /64 as one actor and a /32 as an entire ISP that should almost never be blocked outright. Spamhaus DROP lists netblocks leased or stolen outright by criminal operations, published for firewall and backbone use, where the whole allocation is the finding. — review the widest entries before deploying them.
