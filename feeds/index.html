IPv6 coverage

91 prefixes across 70 distinct /32 allocations, reaching 11,488,576 /48 sites. No individual addresses: every entry is a prefix.

All IPv6 coverage here comes from one independence class (spamhaus_drop_v6). These records are published on that source's precision alone — the same basis as a large share of the IPv4 feed — so the limitation is concentration, not quality: nothing corroborates them, and nothing covers for them if that source degrades.

The widest entry is a /29. General IPv6 practice treats a /64 as one actor and a /32 as an entire ISP that should almost never be blocked outright. These are wider on purpose: Spamhaus DROP lists netblocks leased or stolen outright by criminal operations, published for firewall and backbone use, where the whole allocation is the finding. Review the widest entries before deploying them.

Adjacent prefixes

Listings that sit next to each other in address space. Contiguous allocations under common control are a stronger signal than the same number of unrelated listings. They are reported, not merged: merging would diverge from what the upstream published and lose the per-entry listing reference.

Check an address

Runs entirely in your browser. Nothing is sent anywhere, and no query is logged.

Set it up

iptables with ipset

Loads the list into an ipset and drops matching traffic. Re-run the first command from cron every 6 hours to stay current.

curl -sS https://neilweitzel.github.io/xfeeds/iptables.ipset | sudo ipset restore -!
sudo iptables -I INPUT -m set --match-set xfeeds src -j DROP

IPv6

An ipset holds one address family, so IPv6 needs its own set and its own rule. Skip this if you are single-stack IPv4.

curl -sS https://neilweitzel.github.io/xfeeds/iptables6.ipset | sudo ipset restore -!
sudo ip6tables -I INPUT -m set --match-set xfeeds6 src -j DROP

Keep it updated

# /etc/cron.d/xfeeds
17 */6 * * * root curl -sS https://neilweitzel.github.io/xfeeds/iptables.ipset | ipset restore -!
17 */6 * * * root curl -sS https://neilweitzel.github.io/xfeeds/iptables6.ipset | ipset restore -!

nftables

curl -sSO https://neilweitzel.github.io/xfeeds/nftables.conf
sudo nft -f nftables.conf

Then reference the set in your ruleset:

nft add rule inet filter input ip saddr @blocklist4 drop

pfSense or OPNsense

Both can fetch a URL table on a schedule — no scripting needed.

Firewall → Aliases → Add
  Type: URL Table (IPs)
  URL:  https://neilweitzel.github.io/xfeeds/high-confidence.txt
  Update frequency: 1 day

Then Firewall → Rules → WAN → Add
  Action: Block
  Source: the alias you just created

MikroTik RouterOS

/tool fetch url="https://neilweitzel.github.io/xfeeds/high-confidence.txt" dst-path=xfeeds.txt
/import file-name=xfeeds.txt

Or use an address list with a scheduled script. Note that RouterOS does not skip # comment lines automatically — strip them first.

Cloudflare

Create an IP Access Rule list from the feed. The free plan caps custom lists, so the high-confidence tier is the right one to use.

curl -sS https://neilweitzel.github.io/xfeeds/high-confidence.txt | grep -v '^#' > xfeeds.txt
# Then: Cloudflare dashboard → Manage Account → Configurations
#       → Lists → Create new list → upload xfeeds.txt

Why "independence class" matters. Many public blocklists copy from each other, so counting files as votes manufactures false confidence. Sources that share upstream data share a class, and each class votes at most once. Sources marked scoring only help decide what is malicious, but their data is never republished here because their licences do not allow it.

What the whole corpus looks like

The feeds above contain only what we are licensed to republish. These figures cover everything we look at — 266,248 addresses from 24 sources across 11,374 networks — including sources whose licences forbid us republishing their addresses. A count is a derived fact, not an extract, so those sources can finally show their work here.

No individual address appears in this section, and named ASNs or countries with fewer than 5 addresses are folded into an unnamed bucket (7,301 networks) so no cell can identify a single address. That is a deliberate limit, not an oversight: a “top offending addresses” list would be the data itself wearing a hat.

Two tiers, and which one you want

Everything above is the primary feed. Use it for anything, including commercial work. No source in it restricts commercial use.

Some good public feeds allow redistribution but forbid commercial use. We cannot put those in a file that anyone might use at work, so they are republished separately in the non-commercial tier under CC BY-NC-SA 4.0. It is larger — 8,109 addresses versus 4,658 — because it can include the Turris Sentinel router-sensor data and StopForumSpam's toxic ranges in full rather than just counting them as corroboration.

Home lab, personal server, school, charity, or research? Take the non-commercial tier — it sees more. At a company, or building anything anyone pays for? Take the primary feed. That is not a nag; the licences genuinely differ, and LICENSE.txt in that directory spells it out.

Licensing and credit

xfeeds compiles publicly available feeds and is not sold. Where a source forbids redistribution outright it is used for scoring only, or excluded. Where it permits redistribution but forbids commercial use, it goes in the non-commercial tier. Every published file names its contributing sources and carries their terms. Full per-source reasoning, including the sources we rejected and why, is in DECISIONS.md.

Spamhaus attribution travels with the data as their terms require. Threat data also provided by IPThreat at https://ipthreat.net, and by the Turris Sentinel project at CZ.NIC (CC BY-NC-SA 4.0, non-commercial tier only).

False positives

No block list is perfect. If an address here is legitimate, open an issue — those are triaged ahead of everything else, and confirmed mistakes are added to a permanent allowlist so they cannot come back.
